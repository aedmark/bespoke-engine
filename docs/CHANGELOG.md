# Changelog

User-visible changes to the BeSpoke Engine, newest first.

## Unreleased

- The Tide Beacon colour-cycling proof (`--tide-beacon`, `proofs/wasm_deck.zig` deck 18) and standalone showcase page (`site/tide-beacon.html`): four simultaneous palette colour cycles animate waterfall foam, ocean surf, brazier embers, twinkling stars, and the Keeper's hand lantern at 60 Hz on one static 320x180 PNG backdrop without changing world state (`P49-01`, `D-190`).
- Text-first project template (`P49-02`, `D-191`): `bespoke init <name> --template text` scaffolds a turn-based parser adventure with a transcript, command field, hint button, AudioWorklet sound, and optional animated room picture, supported by `wasm_submit_command` and `wasm_set_animation_clock` in the browser exports.
- Palette colour cycling (`P49-01`, `D-190`): top-level `cycle "<c1>" "<c2>" ... [every N]` rotates declared palette colours forward every `N` 60 Hz display frames across drawn art on both desktop and browser, stored in an optional `CYCL` package section that 1.0 readers skip cleanly.

## 1.0.1 - 2026-11-26

- Generated projects pin their CI engine checkout to `refs/tags/v1.0.0` and drop the pre-1.0 test setup fallback (`P48-06`).
- VM and bytecode boundary hardening (`D-189`): 64 KiB bytecode limit (`MAX_BYTECODE_LEN = 65535`), linear `bytecode.validate` checks on `.bspk` package save/load, runtime bounds/jump/cue-arg/stack checks in `src/vm.zig`, checked `u16`/`i16` compiler emissions (`BytecodeTooLarge`, `JumpOffsetTooLarge`), and restored fiber/interrupt PC validation in `src/save.zig`.
- Audio thread safety and synthesizer guards (`src/audio.zig`): lock-protected soundtrack switching with ring-buffer compaction and synchronized volume snapshots in `AudioBridge`, zero-divisor/step-count/`i64` phase guards in `ChiptuneSynth`, and host-vs-BGM SFX isolation.
- Atomic saves, world symmetry, witness ordering, and `ScriptFiles` containment: write-flush-rename with best-effort `.bak` backup in `SaveManager.save_slot_versioned`, `World.intern_relation` bounds, clearing `recently_expired_count` in `World.restore_state`, preserving `facts.capacity` in `World.clone`, ascending `EntityId` witness ordering in `dilemma.reveal`, and realpath-bound reads in `ScriptFiles.read`.
- Compiler, world, VM, and spatial scaling fixes: `MAX_STMT_DEPTH = 64` parser nesting limit (`NestingTooDeep`), `World.find_all_matches_capped` and `O(N)` `RowKey` deduplication in `when each` and cross-build save loads, overflow-safe `Point2D.distance_to`, `SpatialGraph.add_waypoint` cap (`WaypointLimitExceeded`), and `MotorAgent.step_tick` zero-speed and diagonal-stall fixes.
- WebAssembly and display-name isolation: in-place `WasmRuntime.init_in_place` eliminating the ~1.2 MiB stack copy, alias-free `wasm_decision`/`wasm_dilemma` query copies, and per-world `shown_owner` display-name isolation in `dialogue_panel.zig`.

## 1.0.0 - 2026-11-26

### What 1.0 promises

- **Script language ([`script_spec.md`](script_spec.md)):** Every frozen 1.0 construct, naming rule, and error kind is pinned by the 47-case language conformance suite (`zig build test-conformance`) and governed by the [deprecation policy](CONTRIBUTING.md#deprecation-policy).
- **File formats ([`COMPATIBILITY.md`](COMPATIBILITY.md)):** Packages use `BSP1` format 1 tagged sections (`NAME`, `PLAC`, `CODE`, `RULE`, subsystem sections, `IMGS`, `ARTB`, `TEXT`), and saves use `BSV1` version 1. Every 1.x reader loads every earlier 1.x package and save; pre-1.0 files (`BSPB`, `BSAV`) are refused with a clear diagnostic.
- **Supported host APIs ([`API.md`](API.md)):** The supported Zig host contract is verified at compile time by `tests/supported_host.zig`, and the 21 supported browser WebAssembly exports are pinned by `tests/test_browser_exports.py`; unlisted declarations remain internal.
- **Release targets:** Linux x86_64 (static CLI and SDL2 desktop) and modern browsers (Chrome and Firefox, offline and phone width); macOS builds in the starter CI workflow; Windows remains deferred until a contributor maintains it (`D-143`).

### Changes in 1.0.0

- Release hand-test polish (`P48-05`): Save/Load drawer tab labels and slot cards fit within bounds (`src/display/renderer.zig`), the stock runner handles all interactive verbs with consistent `src/phrase.zig` status banners (`src/runner.zig`, `src/scaffold/main.bespoke.tmpl`), `scenarios/night_watch.bespoke` adds interactive prop handlers, and harsh `o5 @1`/`@5` MML scores in `scenarios/night_watch.bespoke`, `src/scaffold/main.bespoke.tmpl`, `docs/AUTHORING.md`, `docs/script_spec.md`, and the tutorial patch in `docs/FIRST_GAME.md` are re-voiced cleanly.

- Wider 5x7 canvas font (`D-179`): display names, dialogue, hints, and stage labels render Latin-1 Supplement, common Latin Extended-A letters, and typographic punctuation identically on desktop and browser, unsupported characters fall back cleanly to a single `?`, and truncation/wrapping count characters rather than bytes.
- Case-only name twins refused at compile time (`D-177`): declaring or referencing an entity, relation, routine, or scene name that differs from an existing name only in ASCII letter case (`LAMP` beside `Lamp`) is now a compile error whose help names the existing spelling, while lowercase variables, identical spellings across distinct namespaces, and spoken text stay allowed.
- One `host` question per declared feature and matching browser exports (`D-176`): `host.hint`, `host.decision`, `host.dilemma`, and `host.known_value` (plus `Session` wrappers) replace direct internal table/module reads, and the browser runtime exports `wasm_hint`, `wasm_decision`, `wasm_dilemma`, `wasm_known_value`, `wasm_query_ptr`, and `wasm_query_len` alongside the `[H]` hint key on the stock and showcase pages.
- Unique arranged music for every proof (`proofs/music.zig`, `proofs/art.zig`): added twelve multi-section arrangements (`living_village`, `lamp_point`, `caustic_grog`, `saltmarket`, `weathercock`, `fire_escape`, `observatory`, `valerius`, `lamplighter`, `long_gallery`, `word_foundry`, `cinder_table`), each running over two minutes before repeating, and wired `art.soundtrack` on Deck 14 (`lamplighter.html`).
- Interactive web pages for The Long Gallery (`site/long-gallery.html`), The Word Foundry (`site/word-foundry.html`), and The Cinder Table (`site/cinder-table.html`), bringing all eighteen standalone proofs and Harbour to the browser showcase (`proofs/wasm_deck.zig` decks 15 to 17). `WasmRuntime` adds read-only `watch_scene` capture (`D-138`) so The Long Gallery can toggle into the Locked Studio without moving Audra.
- Turn-based games (`D-188`): `clock: turns` makes the clock move only when the player acts. Every command the game understands takes one turn, a mistyped one takes none, saves and hints never do, and a walk passes time until it arrives. The stock window, the browser, and `bespoke run --headless --input` all count the same way. Realtime stays the default.
- Breaking: packages and saves have their 1.0 formats (`D-172`, `D-174`, `D-187`). A package (`BSP1`) is a set of tagged sections, one per part of the program it uses, so a later 1.x can add a section without breaking 1.0 readers: an unknown optional section is skipped and an unknown required one refused. A save is `BSV1` version 1. Packages and saves from before 1.0 no longer load; rebuild a package from its script with `bespoke compile`. Browser builds link only the package readers their games need, which takes the showcase's proof module from 1,074,277 to 890,178 bytes. Loading a package no longer doubles its walkways.
- `when each Holds(who, Sword):` fires once for each row as it starts to hold, with `who` bound in the body (`D-170`, `D-186`). Rows that start together run in name order, a row that stops and starts again fires again, and saves and rewinds keep which rows hold. A plain `when` rule is unchanged. Packages are format 37 and saves format 5.
- A game may span files (`D-169`, `D-185`): `include "acts/one.bespoke"` at the top level reads another file in place, once, with every path from the main script's folder, and an error in an included file names that file and its line. The Lamplighter's Round now keeps its art and its talk in their own files, and compiles to the same package as before.
- Rewinds and loads are exact (`D-168`, `D-184`). A rewind or scrub now restores every routine where it stood, walking people where they were, the scene on stage, and the dice, so the same action after a rewind rolls the same; a script whose rolls are for variety writes `rewinds reroll`. Scripts never set a seed: headless runs use 42, `bespoke run --seed N` picks another, and a new game in the window or a browser page takes one from the clock, which saves keep. A branch world rolls from dice of its own and never changes the present's. Saves are format 4 and packages format 36; older files load as before.
- Authors tune the numbers behind dilemmas and raise sanity ceilings (`D-167`, `D-183`). `tiers 8 and 4` in a dilemma moves its strong and moderate boundaries, `drift cap 3` lets it move each axis three steps, and `drift step 4` under an axis sets the points per step; without them the numbers are the old 7, 3, 2, and 5. `limit decisions 48` raises one of nine counts (goals, needs, decisions, options, dilemmas, axes, spells, words, hints) up to eight times its default, and going past a limit names the line that is needed. A need may write hint tiers past 3, and asking past its last tier repeats that tier. Packages are format 35.
- Art is full colour (`D-166`): PNG files keep every colour, and a `palette:` is now an optional style rule, so a game that declares one has its art held to those colours and is told which pixel strays. Packages store each image as a standard QOI stream (`D-182`), which shrinks The Lamplighter's Round's package from 127,001 to 33,989 bytes and the showcase's proof module by 89,305 bytes. A game's art may total 2,097,152 pixels. `Canvas.draw_image` no longer takes a palette. Packages are format 34; older packages draw as before.
- Scripts choose what each thing shows: `look LampLit: LampSheet` names one way of showing a sheet, with its own animations, and `remember Looks(Lamp, LampLit)` switches to it, so a save or rewind shows the right look (`D-181`). `part Flame of Lamp at 0 -14` draws one thing above another and clicks it as its host, and a prop with a sprite and an area draws where its area is. The Lamplighter's Round now lights its lamps from its script. Packages are format 33.
- The engine's bookkeeping relations are named with `#` (`#DialogueOpen`, `#SceneScore`), so they can never clash with a script's, and the State drawer hides them until its `E` key (`D-180`). The engine relations scripts may test, such as `Knows`, `Chose`, and `AgendaState`, are listed as reserved words in the script spec. `bespoke check` can now print warnings; it warns when a script declares a relation a later engine release also uses. Packages are format 32.
- Scripts set what players read: `name ExposureSlip: "the slip from the darkroom"` names an entity on screen, in speech, hints, and replies, and `phrase HintRoom: "Seek out the {room}."` replaces one of the engine's sentences, listed with their placeholders in the script spec (`D-179`). The English defaults are unchanged. Text may be UTF-8; until a wider font lands the window draws other characters as `?`. Packages are format 31.
- Saves record which build of the game wrote them, and the window refuses a save from another build with "Slot #N is from another version of the game" instead of loading it into mismatched code (`D-162`). Scripts declare `save version N`, which packages (format 29) and saves (format 3) carry; loading an older save into a patched build with the same save version arrives next.
- A patched build that keeps the same `save version` loads older saves: facts are matched by name, routines restart from their beginning, and a `when` rule whose condition already holds does not fire again (`D-162`). Each relation now holds either entities or numbers in its second slot, and a script that uses one relation both ways no longer compiles (`D-178`). Packages are format 30.
- `bespoke run --headless` can play typed commands from a file (`--input moves.txt`, lines of `<tick> <command>`) and print the facts a run leaves (`--facts`); `bespoke check --kind` names the error's kind. A language conformance suite (`zig build test-conformance`) uses them to pin every frozen rule as runnable scripts (`D-173`).
- A time branch closes when either `ConvergenceReady` or `LoopClosed` holds, as `D-073` describes. Before, a script that mentioned `ConvergenceReady` anywhere could never close on `LoopClosed`.
- A cue handler's body reads its parameters: in `on cue Greets(Hero, other):`, `remember Met(Hero, other)` records the entity the cue named, and a variable the `where` guard matched is read the same way (`D-161`). Before, the body wrote about an entity literally called `other`. Package format version 28 carries the new instructions.
- Breaking: the first letter of a name decides what it is (`D-161`). Names of things start with a capital letter, and a lowercase name is a variable that something must bind, so `entity hero`, `relation lit(x)`, and `remember Holds(Hero, sword)` are now compile errors, with help suggesting the capitalised name. A `when` rule's body cannot use its trigger's variables yet.
- Breaking: a state word after `is` names the capitalised relation, so `now Lamp is lit` and `Lit(Lamp)` are one fact (`D-161`). A host that looks a state up by name now asks for `Lit`, not `lit`.

- Several `on cue` handlers may share a signature: they are tried in source order, and a handler whose `where` guard fails passes the cue to the next one before a broader handler is tried (`D-160`). Before, the last handler silently replaced the others and the script's package would not load. A handler placed after an unguarded one with the same signature can never run and is now a compile error naming both lines. Package format version 27 carries the order.

- The authoring guide and the manual cover pixel art: palettes, images from PNG files, backdrops, animated sprites, and clickable areas, with the art limits an author meets.

- Props click where they are drawn: `area ShopDoor: 96 62 24 42` makes a painted door clickable anywhere on it, and people and props drawn as sprites are clicked anywhere in their frame (`D-158`). Package format version 26 carries areas.

- The Lamplighter's Round is a new proof with its own page (`site/lamplighter.html`, `--lamplighter`): at dusk Nell Brindle, a late lamplighter, lights two streets' lamps before the watch walks his round, once a jackdaw has been bribed out of one. Every room, person, and prop is pixel art imported from PNG files when the game is built, and people walk and idle in animation.
- Proof pages may be up to 2 MiB (`D-157`), up from 1.25 MiB, and each WebAssembly module up to 1.5 MiB (`D-159`), up from 1 MiB, now that a proof carries its own art.

- PNG import: `bespoke import art.png --name Lamp [--frames 12x20] [--script game.bespoke]` prints the image as rows of palette codes with the palette lines it needs, and `image Lamp from "lamp.png"` compiles a PNG beside the script when it is run, compiled, or checked from the command line. Colours map exactly; a partly transparent pixel or a 257th colour is refused, as are interlaced and 16-bit files (`D-156`).

- Scripts can declare pixel art: a `palette:` of up to 256 colours, `image` blocks written as rows of palette codes and cut into frames, a `backdrop:` for a scene, and a `sprite` for a person or prop with an idle and a walk for each direction, timed in 60 Hz display frames. A scene with a backdrop hides its walkways and resting marks; people and props stand on their spots. The compiler names the line of an unknown image, a missing frame, an unknown colour code, and other art mistakes. Package format version 25 carries the bindings (`D-155`).

- A host can draw pixel art: `Canvas.draw_image` paints one frame of an indexed image at four times its size, leaves palette index 0 transparent, and works the same on desktop and in the browser. The message band check measures the pixels an image paints, so a sprite that reaches the band fails like any other prop (`D-154`).

- A package can carry pixel art: one palette of up to 256 colours and indexed sprite sheets and backdrops, with frames up to 320x180 (`D-152`, `D-153`). Package format version 24 holds it, earlier packages load with no art, and a malformed palette, size, name, or pixel index is refused with an error that names it. Scripts cannot declare art yet; drawing, declarations, and PNG import follow in Phase 46.

## 0.4.0 - 2026-11-21

- Valerius and the Bread is a new proof with its own page (`site/valerius.html`, `--valerius`): in a hard winter at the hill-fort of Greyhold, Hesper learns what Captain Valerius values and appeals to it to save her brother Tam, who stole a loaf. His red lines refuse a hanging and a bribe, Mercy and Loyalty end the winter differently, and the outcome drifts his Mercy into the spring scene (`P45-06`).
- An appeal can name any declared value and the weighed axis it moves, as in `appeals 8 to Loyalty toward Mercy` (`D-150`).

- The player can appeal to a character's values: `appeal to mercy` moves that character's next weighing of a dilemma toward mercy by the amount its `appeals` line gives, once the player has learned that the character holds that value, by watching a weighing or by asking. An appeal to a value the player has not learned is refused. Learned values make goal hints speak from the player character's knowledge. Package format 23 carries appeal lines, and versions 1 through 22 still load (`P45-05`, `D-149`).

- A dilemma's `drifts` lines change a character's values over a long game: when an outcome such as `Repaid(Thief)` becomes true after the dilemma has been weighed, its points add up, and every 5 move the value one step, at most 2 steps per dilemma and never past -10 or +10. Drift is saved, rewound, and replayed exactly. Package format 22 carries drift lines, and versions 1 through 21 still load (`P45-04`, `D-148`).

- The showcase pages load faster: the browser proof module is 668,536 bytes, down from 836,726, because a deck that plays script source no longer carries the package loader (`D-147`).

- A `dilemma` weighs a character's value on one axis against another, plus `leans` lines read from world facts, and answers with one of five tiers: strong or moderate toward either axis, or neutral. The character speaks the tier's line and the dilemma fires its cue with the tier's action; a neutral character asks to be shown evidence and weighs again when something is presented. A dilemma that misses a tier is a compile error. Package format 21 carries dilemmas, and versions 1 through 20 still load (`P45-03`, `D-146`).

- A character's red lines, such as `red lines Valerius: Execute`, are options it never takes: a decision skips them before scoring, so a vetoed option is never chosen even when it would score highest, and a decision with nothing left chooses nothing. A red line that names no option offered to that character is a compile error. Package format 20 carries red lines, and versions 1 through 19 still load (`P45-02`, `D-145`).

- Scripts declare their own value axes, such as `axis Mercy between Vengeance and "Condoning Harm"`, and give a character a value from -10 to +10 with `remember Mercy(Valerius, -3)`. A value outside the range is a compile error, a run-time write past it stores the limit, and the state inspector lists the value on its character. Package format 19 carries axes, and versions 1 through 18 still load (`P45-01`, `D-144`).

## 0.1.0 - 2026-11-16

- Published the first versioned BeSpoke Engine release (`P37-03`). `bespoke --version`, `bespoke-proofs --version`, and `build.zig.zon` report `0.1.0`; `zig build version-check` runs both CLIs and rejects a mismatch before a release is tagged.
