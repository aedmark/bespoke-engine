# Architecture

How the BeSpoke Engine fits together. This document maps the core components, data flow, invariants, and boundaries. Rationale and alternatives live in [DECISIONS.md](DECISIONS.md).

- **Props click where they are drawn (P46-05, D-158):** `area <Prop>` rectangles (`CompiledProgram.art.areas`) and declared sprite frames are what `hit_test_hotspot` and `hit_test_actor` reach, and what the debug overlay outlines on hover (`renderer.sprite_box`, `area_rect`); a walk to an area prop aims for the mark nearest its foot (`prop_anchor`, and `WasmRuntime.reach_mark` in the browser). A prop with an area and no drawing is part of the backdrop.
- **PNG is decoded only on the command line (P46-04, D-156):** `src/png.zig` turns a PNG into RGBA within the sheet limits and `src/art_import.zig` keeps each pixel's colour (`to_pixels`), holding it to the script's `palette:` when one is declared (D-166). `bespoke import` maps a PNG onto palette codes and writes an inline block; `image X from "file"` reaches the parser through a `FileSource` that only the runner supplies (`ScriptFiles`, the script's own folder). Freestanding builds compile the decode path out, so the browser module never carries it.
- **Scripts declare art; the window draws it by binding (P46-03, D-155):** the parser resolves `palette:`, `image`, `backdrop:`, `sprite`, `look`, and `part` declarations into `CompiledProgram.art`, whose `backdrops` and `sprites` bind images to scene and entity ids. `DisplayWindow.set_art` borrows them; `render_frame` draws a scene's backdrop in place of the theme and hides walkways and resting marks, and draws a sprite in place of a prop or person, choosing its animation from `RenderEntity.heading` and the window's `animation_clock`. The clock counts shown frames on desktop and comes from elapsed time in the browser; it never enters the world, so goldens fix it.
- **Images are drawn by one canvas call (P46-02, D-154):** `Canvas.draw_image` paints a frame of an image as 4x4 blocks at a frame position, leaves transparent pixels alone, and records the frame's opaque bounds in the rect probe under the current layer, so the band check measures image art as it measures drawn props. Desktop and browser share it through the canvas (D-097). Until P46-03 a theme hook calls it.
- **`when each` keeps its rows as VM state (P48-16, D-170, D-186):** a rule marked `each` finds matching rows with `World.find_all_matches_capped` (bounded join materialization), deduplicates and diffs them with `VM.RowKey` hash sets, fires the rows not held at the last evaluation in name order, and keeps the set in `ReactiveRule.rows`, which saves and rewind snapshots carry. A row's body interrupts its first subject's routine with the row's values pushed above that routine's stack, read through `Fiber.local_base`, or runs as that subject's own fiber.
- **A turn clock is the host's, declared by the script (P48-22, D-188):** `clock: turns` sets `CompiledProgram.turn_clock`. The engine's tick is unchanged; each host decides when to call it. The stock window, `host.Session` (`clock_runs`, `take_turn`), and the browser runtime (`clock_runs`, and a click that fires a cue) tick once per resolved command or acting click and on their timer only while the player walks; headless runs type `--input` lines in order. `host.run_command` marks a resolved line with `CommandReply.turn`.
- **A game may span files, expanded before lexing (P48-15, D-169, D-185):** `compiler/includes.zig` reads each `include` through the compile's `FileSource` (the runner's `ScriptFiles`, held to the main script's folder), skips a file already read, and builds one text with a map from each line to its file and line. The lexer, parser, and code generator see only the expanded text; `check_source` maps every diagnostic and warning back through the map (`CheckResult.file`). A package holds the expanded program, so no runtime reads includes.
- **Rewinds and loads restore the whole run, dice included (P48-14, D-168, D-184):** `roll` draws from `VM.dice` (`src/dice.zig`), seeded by the host (42 headless, the clock in a real window or a browser page, `--seed N` on the command line), never by a script. A `host.Timeline` run snapshot is the save's own serialization (world, walking agents, the VM's fibers, scene, and rule edges, the dice, the temporal envelope), so `Session` rewinds and scrubs are loads from memory; the browser's ring slots hold the same parts through `save.write_spatial_state` and `save.write_vm_state`. `rewinds reroll` makes a restore keep the current dice. A live branch rolls from `TemporalHypervisor.branch_dice`, seeded from `run_seed` and the fork tick, which the host binds as `VM.branch_dice`, so the present's dice never move inside a branch.
- **Pixel art is package data outside the world (P46-01, D-153, D-166, D-182):** `CompiledProgram.art` holds images of RGBA pixels (`src/image.zig`), alpha 0 or 255 and a transparent pixel all zeroes, with no palette; a frame is at most 320x180 and tiles its sheet exactly, and a game's art is at most 2,097,152 pixels (8 MiB decoded, half the browser heap). The package stores each image as a standard QOI stream (`src/qoi.zig`). `Art.validate` is the single gate: the writer refuses invalid art and the loader checks each count and size before reading the bytes behind it, so a renderer may index any stored pixel without checking again. Art never enters the World, `.sav`, or a snapshot. Script declarations, drawing, and PNG import are P46-02 to P46-04.
- **Value axes are bounded properties (P45-01, D-144):** an `axis` declaration interns its virtue as a property relation and records the axes in `CompiledProgram.axes` (`src/value.zig`). `World.bound_relation` gives the relation a signed range of -10 to +10, stored as two's complement in the value slot; `World.remember`, `restore_state`, and `clone` clamp into it, so no reader sees a value outside the range. Bounds are program data, not fact data: the compiler or package loader declares them and the world snapshot does not carry them. The inspector lists a bounded value as a signed number. Enforced by: the P45-01 tests in `src/world.zig`, `src/value.zig`, `src/compiler/codegen.zig`, `src/display.zig`, and `src/package.zig`.
- **Persuasion is an appeal to a learned value (P45-05, D-149):** `host.appeal` and the engine frame `appeal to <value>` check that the actor knows `<Axis> of <Character>` (`value.known_value`) and that an open dilemma of that character lists the value, then record `#PendingAppeal(Dilemma, Axis)`, the history fact `Appealed(Character, Axis)`, and fire `Appeals`. `dilemma.step` adds the appeal's points to the next weighing and forgets it, re-weighs a neutral dilemma that has a pending appeal, and teaches the leaned value to everyone in the actor's room after a non-neutral weighing. `hint.query` treats an axis object about a character as that known value. Enforced by: the P45-05 tests in `src/host.zig`, `src/compiler/codegen.zig`, and `src/package.zig`.
- **Drift is integer facts from dilemma outcomes (P45-04, D-148):** each `drifts` line of a dilemma watches its fact; on a rise after the dilemma's first weighing, `dilemma.step` adds its points to the actor's `#<Axis> drift` accumulator and spends whole steps of 5 into the value, at most 2 per dilemma and axis, discarding points past the bound or the -10..+10 range. Accumulators, steps spent, line edges, and the weighed state are World facts on relations whose generated names hold a space, so save, rewind, branch restore, and replay need nothing new. Enforced by: the P45-04 tests in `src/dilemma.zig`, `src/compiler/codegen.zig`, `src/host.zig`, and `src/package.zig`.
- **Dilemmas weigh two axes into five tiers (P45-03, D-146, D-183):** a `dilemma` compiles into `CompiledProgram.dilemmas` (`src/dilemma.zig`). `host.tick` runs `dilemma.step` after decisions: on a rising trigger it computes axis minus counter-axis plus the leans that hold, picks one of five tiers by the dilemma's own boundaries (7 and 3 unless its `tiers` line says otherwise), emits the tier's line as a `say` cue, records `Chose(Dilemma, Action)`, and fires the cue with the actor and the action. Neutral waits in `AwaitsEvidence` and weighs again when the count of `Presented(Actor, _)` facts grows. `DilemmaState`, `#EvidenceSeen`, and `Chose` are World facts, so save, rewind, and branch restore need no snapshot. Enforced by: the P45-03 tests in `src/dilemma.zig`, `src/compiler/codegen.zig`, `src/host.zig`, and `src/package.zig`.
- **Red lines are program data that veto before scoring (P45-02, D-145):** a `red lines` declaration compiles into `CompiledProgram.red_lines`, one set of option entities per character. `decision.step` skips a vetoed option before it checks knowledge or scores it, so no score revives it; when every offered option is vetoed the decision chooses nothing. Red lines are not facts, so no script, save, rewind, or drift lifts one. The compiler and the package loader both reject a red line that names no option offered to that character, and a decision whose options are all vetoed. Enforced by: the P45-02 tests in `src/decision.zig`, `src/compiler/codegen.zig`, `src/host.zig`, and `src/package.zig`.
- **Decisions are program data and the choice is a fact (P44-05, D-137):** a `decision` declaration compiles into `CompiledProgram.decisions`: an actor, a cue, trigger lines, and options with their scored lines. `src/decision.zig` offers only options the actor knows (the spell discovery rule), sums the satisfied lines, breaks a tie by declaration order, and fires the cue with the actor and the winner. `DecisionState` is a property and `Chose(Decision, Option)` is a set fact, so save, rewind, and branch restore need no snapshot. Enforced by: the P44-05 tests in `src/decision.zig`, `src/compiler/parser.zig`, `src/compiler/codegen.zig`, `src/host.zig`, and `src/package.zig`.

## The Shape, in One Paragraph

The BeSpoke Engine inverts traditional game engine architecture into an **Engine-as-Spine** model (D-001). The Zig runtime is `main()`, owning the master simulation clock, entity IDs, contiguous relational fact tables (`MultiArrayList(Fact)`), and cooperative fiber scheduler. Game scripts written in the BeSpoke domain-specific language are compiled by a hand-written Zig front-end directly into compact custom bytecode (D-002). Downstream graphics and audio (an SDL2 window, or a WebAssembly canvas in the browser) act as stateless peripheral consumers that read a double-buffered snapshot of the simulation state each frame, and send player input back to the host as actions; they never write World facts themselves.

## Memory Layout & Core Structs (Zig)

Relational facts are stored using Zig's native `std.MultiArrayList` for optimal CPU cache utilization (Structure-of-Arrays layout):

```zig
const std = @import("std");

pub const EntityId = enum(u32) {
    none = 0,
    _,
};

pub const RelationKind = enum(u16) {
    _,
};

pub const Fact = struct {
    subject: EntityId,
    relation: RelationKind,
    object_or_value: u32, // EntityId or immediate scalar value (D-007)
    expires_at_tick: u64, // 0 = permanent
};

pub const World = struct {
    facts: std.MultiArrayList(Fact),
    allocator: std.mem.Allocator,

    pub fn init(allocator: std.mem.Allocator) World {
        return .{
            .facts = .{},
            .allocator = allocator,
        };
    }

    pub fn deinit(self: *World) void {
        self.facts.deinit(self.allocator);
    }
};
```

## Invariants

- **Resource exhaustion is explicit (P39-02, D-109).** The World keeps its existing arena and preallocated fact capacity. The VM reclaims halted fibers only when a new spawn needs space, preserves the IDs and order of survivors, and retains save reader compatibility. The host looks up the initial routine by ID because a fiber's slot can move. [SECURITY.md](SECURITY.md#resource-limits) lists the enforced ceilings and tests.

Rules that hold everywhere across the engine and runtime:

- **The browser plays items where it draws them (D-094):** the item tray is the desktop's (`renderer.inventory_layout`, in the order items were first named), and drawing and clicks use that one layout, so a box is clicked where it is drawn. Enforced by: the D-094 tests in `src/wasm.zig` and `proofs/wasm_deck.zig`.
- **Doorways are shared and every mark is on stage (D-100):** a game's exits are one `host.Exit` list used by its desktop `Session` and its browser deck; a plain walk ending on a doorway, or a walk asked for on one, changes rooms, and a walk to act on something does not. The compiler keeps every mark and prop within the stage (`codegen.stage_x`), and proofs that place marks or casts do it in one function both surfaces call. Enforced by: the D-100 tests in `src/host.zig`, `src/compiler/codegen.zig`, and `proofs/wasm_deck.zig` (every deck's marks on stage; Barbs through its doorways).
- **A frame may show a room the VM is not in (P44-06, D-138):** `DisplayBridge.capture_scene` fills a frame from a named room, labelled as that room and carrying its `#SceneScore`, while `vm.current_scene` and every fiber state stay where they were; `capture_frame` is the same call with the VM's scene. The world and every fiber already advance in every room, so a watched room shows agenda-driven and routine-driven characters alike. A transition sets the scene and fires its cue; it pauses no fiber (D-139). Capture reads only and saves nothing, so a rewind needs no view state. Enforced by: the `P44-06` test in `src/display.zig`, the `P44-07` test in `src/vm.zig`, The Long Gallery's `long_gallery.txt`, and its watched frame in `render.txt`.
- **Proof art clears the message band (D-123, D-124):** a proof's rooms, marks, and labels sit above the log band's highest top, four rows plus the command bar (504 pixels at 1280x720), so no message covers a room name, a sign, or a puzzle item. A mark whose name would still reach the band is labelled above the mark instead (`mark_label_needs_air`, which counts the command bar whether or not the window shows one), and a label placed above stays above when its place is taken, climbing a tier rather than falling back under the band. Hover prompts obey the same rule, a person's prompt moving above them when the space below reaches the band, while the dialogue panel may cover the band's air because it is lifted clear of the log's own rows (D-127). A label that would sit in the band lifts to the band's top row instead, and the rule holds on both surfaces from one helper: `src/display/band.zig` owns the rows, the measurement, and the report, and both goldens call it (D-128). Text records the layer it was drawn on, so the log's rows, the bars, and the panel are skipped by kind while world text is measured on every other layer. Every recorded scene also writes the smallest gap its lowest stage draw leaves above the band, and the render golden fails a scene under an eight-pixel floor, naming the draw and the row it ends on (Q-017, D-133). Enforced by: the D-124 label tests in `src/display/renderer.zig` and `src/display/text_layout.zig`, the D-127 prompt test in `src/display/renderer.zig` and the D-127 badge test in `src/display/text_layout.zig`, the layer-tagging test in `src/display/canvas.zig` and the rows test in `src/display/band.zig`, the band check each golden runs (`proofs/render_golden_test.zig` for every scene, progress state, hover, and open dialogue, and `proofs/wasm_golden_test.zig` for every deck beat), which fails when a mark, a prop, a person, or a drawn string reaches the band's rows, the plan and prop geometry in `proofs/art.zig` and `proofs/observatory_puzzle.zig`, and the render and wasm goldens that pin every scene's frame.
- **Lines are logged, not timed (D-099):** `set_cue_banner` adds to a three-line log drawn under the stage, newest brightest, each line wrapped into scale-2 rows (at most four in all); lines never time out, never shrink, and dialogue panels sit above the log. Enforced by: the two D-099 tests in `src/display/renderer.zig`.
- **The player acts from beside its target (D-092):** in the window and the browser, an action other than LOOK on a person or prop reaches the host only after the player has walked to the target's mark, or after a two-tick grace if the host never walks it. Enforced by: the D-092 tests in `src/display/renderer.zig` and `src/wasm.zig`.

- **Deterministic save/restore:** Primary world state resides in a contiguous arena such that saving or restoring is a pure memory copy without pointer swizzling. - **Path previews and paradox guards (`VectorConduit`, `validate_novikov_consistency`, D-027, D-073):** `compute_vector_conduit` precomputes an A* route from an actor to a goal waypoint as a polyline, which the renderer draws as a preview line. - **Asymmetric downstream feedback (Mutations vs. Continuations):** Structural physical mutations in the past that alter downstream reality telegraph their consequences via reactive interrupt cutscenes (`when` interrupts); temporal continuations (container incubation over time) are discovered organically through player inspection in downstream eras without narrative interruption. Enforced by: edge-triggered VM reactive interrupts vs. passive relational fact queries in `src/vm.zig` and `proofs/three_tides.zig` (D-010, D-025, D-026).
- **Unambiguous musical drafts and dispatched weaves (D-029):** A played four-note sequence names at most one draft, forward or reversed, and weaves dispatch only through exact `Weave:caster:draft[:target]` handler keys. In-script weaves wait in `VM.pending_weaves` until the host calls `dispatch_pending_weaves` after `step_tick`. A half-played distaff phrase is host-side input state (`DistaffInput`, D-030) and never enters the world arena. Enforced by: parser draft validation in `src/compiler/parser.zig`, `CompiledProgram.find_weave_handler`, and the `PendingWeavesNotDispatched` save refusal in `src/save.zig`.
- **Society state is facts (D-034):** `Society` holds only configuration and relation ids; every need, activity, stay, crime, rumor, warrant, and arrest is a World fact, so snapshots and saves capture the whole society. Enforced by: `Society` field list in `src/society.zig` and the snapshot-restore test there.
- **Arrival is an edge, fired inside the tick (D-036):** a `when <Actor> arrives at <Mark>:` rule fires once per completed walk at that mark, in the tick the walk completes, and never for resting, passing through, or being placed. Enforced by: `MotorAgent.arrival_pending`, the arrival pass and `clear_arrivals` call in `VM.evaluate_reactive_rules`, and the P32-18 tests in `src/compiler.zig`.
- **Duel and fatigue state is facts (D-035):** `Duel` and `InquiryFatigue` hold only borrowed configuration and interned ids; what a fighter has heard and mastered, tiers, advantage, wins, inquiry counts, and moods are World facts, and duel lines reach the player only through `VM.prune_dialogue_choices`. Enforced by: the struct field lists in `src/duel.zig` and the snapshot-restore test there.
- **Container lifecycle state is facts (D-050):** a vessel keeps one entity identity; contents, volume, damage stage, exposure deadline, and failure waypoint are World facts. `host.tick` initializes declarations before the VM tick and advances expired exposures afterward. Advancement scans governed vessels rather than the bounded recently-expired diagnostic ring. Enforced by: `ContainerSystem` and its snapshot test in `src/container.zig`, plus package and compiler tests.
- **Container pours conserve liquid (D-051):** a successful pour moves the source's entire volume to one compatible empty vessel or changes nothing. Damage stages never move or reset; only the destination's exposure deadline restarts. Movement spill is the sole intentional loss and follows `Carries(holder, vessel)` plus the holder's motor state. A vessel that fails while carried records its holder's waypoint as the terminal location. Enforced by: P23-02 conservation, rejected-pour, deadline, spill, and carried-failure tests in `src/container.zig`.
- **Dialogue state and pruning evidence are facts (D-046, D-058):** A scripted `choice` block writes `#DialogueOpen`, `#DialogueOption`, `#DialogueBody`, and `#DialogueFiber` facts, suspends its fiber, and resumes at the selected body. P27-02 also writes every source branch's text, active flag, and first failed guard as `DialogueBranch*` facts. Snapshots and rewinds therefore carry the offered set and the reason its alternatives were pruned. Generated and older sets without diagnostic relations expose their offered options as active. Enforced by: `src/dialogue.zig` tests and the compiler-to-VM snapshot test in `src/compiler/codegen.zig`.
- **Path selection is World state (P24-01, D-052):** A `path` declaration compiles fact statements into a reserved initializer routine and path-owned routines into entry points guarded by `PathActive`. `VM.select_path` asserts the route once, runs its initializer on the next tick, and refuses a second route; an inactive routine halts before its body. Enforced by: the P24-01 parser, compiler, VM, and `.bspk` round-trip tests.
- **Grid cell state is World facts (P25-01, D-054):** A grid's geometry is static program data in `SpatialSystem.grids`, one per room, and is never saved. Each set cell attribute is one set-relation fact on the grid entity whose value is the cell index, so save, rewind, and temporal branches restore cell state, and empty cells cost no facts. `grid.seed` writes the declared layout once behind a `#GridSeeded` marker, so re-initialisation after a restore never repairs a changed cell. A waypoint in a `blocking` cell is blocked exactly as `WaypointBlocked` is: at walk planning, by world-aware walks only. Enforced by: the P25-01 tests in `src/grid.zig`, `src/spatial.zig`, `src/compiler/codegen.zig`, and `src/package.zig`.
- **The state inspector reads only the frame (P27-01, P27-02, D-058):** it draws from the facts and dialogue branches `DisplayBridge.capture_frame` copied, never from World. The ego layout and next-expiration order are pure functions of that frame, so the same state draws the same picture. The next list reports captured TTL deadlines and never executes a future tick. Facts carry no object type, so a value equal to an entity id is drawn as an edge, except for the engine's known numeric relations. Navigation and the filter are window state, never World (D-059), so moving around the graph cannot change a save; the layout is a pure function of the frame, the focus, and the filter. Enforced by: the P27 tests in `src/display/state_graph.zig` and `src/compiler/codegen.zig`, the State tab key and navigation tests, mutation checks on branch capture, expiry order, selection, and filtering, and the `inspector/` and `inspector-filtered/` render goldens.
- **Typed nouns resolve only in scope (P26-01, D-057):** a noun phrase matches an entity when every word is one of the entity's name words or alias words, and only entities in the actor's room (agents, hotspots, marks) or held through `Carries`/`InInventory` are candidates. Several matches are never narrowed by preference; the interpreter asks which and takes the next line, if it matches no frame, as a noun naming one candidate. Any other line closes the question. A slot takes the words up to the frame's next literal word, so frames never place two slots side by side. The command bar is off unless a host enables it; while focused it consumes every key, so no engine or host binding fires, and Enter only focuses it when no choice balloon is open. Enforced by: the P26-01 tests in `src/command.zig`.
- **Agenda state is World facts (P33-01, D-056):** an agenda's stage is the property `AgendaState(Agenda, Idle | Pursuing | Done)` on its own entity and its cooldown an expiring `#AgendaCooldown(Agenda)` fact, so save, rewind, and branches restore agency. Per target at most one agenda pursues; an existing pursuit is never preempted, and an actor pursues one agenda at a time. Trigger lines are constant patterns evaluated against current facts; the `when` rule engine is unchanged. Interception is a soft interrupt: it requires actor and target idle on the same waypoint, so no motor path is cut mid-edge, and the cue's handler runs on the next tick. A pursuer re-plans only when its target reaches a new waypoint. `Society.walk_to` refuses to move an actor holding `Pursuing`. Enforced by: the P33-01 tests in `src/agency.zig`, `src/host.zig`, `src/compiler/codegen.zig`, and `src/package.zig`.
- **Grid automata are synchronous and live in fact lifetimes (P25-02, D-055):** a fire is a `CellBurning` fact whose TTL is its remaining burn, and smoke a `CellSmoke` fact whose TTL is its linger time, so pruning ends both and a rewind restores their exact age. `grid.step` decides every ignition and flood from the state at the start of the step before applying any, so results do not depend on cell order. It runs in `host.tick` after the VM tick, then hazard states (`InBurningCell`, `InSmokeCell`, `InLiquidCell`) are written to agents; rules see them on the next tick. Programs without grids run neither. Enforced by: the P25-02 tests in `src/grid.zig` (rewind replay, flow cadence, static grids), `src/spatial.zig`, and `src/host.zig`.
- **Ceilings a script may raise are compile-time rules (P48-13, D-167, D-183):** `src/limits.zig` names nine sanity ceilings with their defaults; the parser checks every counted item against the script's `limit` lines once the whole script is read, and each module's `MAX_` constant is the safety cap of eight times the default, which the package loader enforces on untrusted counts. No limit reaches the package.
- **Hints read facts and write none (P44-01, D-134):** a `goal` declaration is program data on `CompiledProgram`; the hint query is a pure function of the compiled goals, the World's facts, and the player entity. It reports the first unmet frontier need whose entities the player knows, phrased as Holmesian, and otherwise the first unmet need in declaration order as the author (D-126). Knowledge is `Knows` or `Believes` about the player, with `Rejects` overriding both. No hint fact exists, so saves, rewinds, and replays report the same hint for the same world. Enforced by: the P44-01 tests in `src/hint.zig` (tiers, frontier, knowledge, authored overrides), `src/compiler/codegen.zig`, and `src/package.zig`, and the Observatory's hint lines in `proofs/golden/observatory_puzzle.txt`.
- **Evidence thresholds read the fact table once (P44-02):** `2 of Clue(_)` counts the facts a pattern matches and `6 points of Clue(_)` sums their third slot, each compared with a u64 total so a long table cannot wrap. The compiler emits `query_count` and `query_points` with a wildcard mask and a threshold; the VM evaluates them in `if`, `wait until` through `eval_condition`, and choice guards through `eval_expr`. Neither path writes a fact. Enforced by: the P44-02 tests in `src/compiler/parser.zig`, `src/compiler/codegen.zig`, and `src/vm.zig`, and the aggregate lines in `tests/fixtures/fuzz/room.bespoke`.
- **Spellbooks are program data and discovery is a fact (P44-04, D-136):** a `spellbook` declaration compiles into `CompiledProgram.spellbooks`: one book of tiered words and the named triples built from them. `src/spell.zig` resolves a name or a triple and checks each word against `Knows` or `Believes` about the caster, with `Rejects` overriding; it writes no fact. A refused combination fires no cue, so a fizzle cannot change state. Enforced by: the P44-04 tests in `src/spell.zig`, `src/compiler/parser.zig`, `src/compiler/codegen.zig`, `src/host.zig`, and `src/package.zig`, and The Word Foundry's transcript.
- **Waypoint locks are World facts (P24-02, D-053):** A path initializer can assert `WaypointBlocked(Mark)`, where the mark entity shares the waypoint's name. `SpatialSystem.walk_to_with_world` reads the active locks and asks `SpatialGraph.find_path_avoiding` for a route without those nodes; the graph itself is unchanged. Locks apply at walk planning, not to an in-flight path. Path-asserted obstacle facts (`Trapped`, `PortalBlocked`, and the guard predicates) feed `can_access_portal`, and `PathActive`-guarded choices prune NPC dialogue. Enforced by: the P24-02 spatial, VM, and compiler-to-VM tests.
- **Script declarations are owned program data (D-045, D-050):** `CompiledProgram` owns compiled society, duel, and degradation declarations. Their slices may borrow stable text from the World's entity-name table and remain valid until `CompiledProgram.deinit`. Hosts initialize `Society`, `Duel`, and `InquiryFatigue` from those declarations; runtime state remains in World facts.
- **One time-travel model for interactive hosts (D-033):** scrubbing restores a snapshot without discarding the future; advancing from a past point discards it. Hosts tick through `host.tick` (or `Session.advance`) so in-script weaves are re-dispatched, and read speech after each tick. Enforced by: `host.Timeline` and `host.Session` tests in `src/host.zig`, and the proof goldens.
- **Centralized Master Simulation Clock & Decoupled Pacing:** Simulation clock ticks advance at a deliberate canonical base rate (`DEFAULT_TICK_INTERVAL_MS = 1000` ms / 1.0 Hz) defined in `src/vm.zig`, strictly decoupled from peripheral 60 Hz display rendering. Interactive runners evaluate clock progression against `DisplayWindow.current_tick_interval_ms`, bounded between 100ms (10 Hz fast-forward) and 3000ms (0.33 Hz slow-motion) with runtime scaling via `[-]`/`[+]` hotkeys, preserving deterministic discrete integer ticks without floating-point delta accumulation. Enforced by: `DEFAULT_TICK_INTERVAL_MS` in `src/vm.zig`, `DisplayWindow.current_tick_interval_ms` in `src/display/renderer.zig`, and runner loops across `src/main.zig`, `proofs/three_tides.zig`, `proofs/weathercock.zig`, `proofs/lamp_point.zig`, `proofs/borrowed_beard.zig`, `proofs/spitting_contest.zig`, `src/runner.zig`, and `proofs/village.zig` (D-001, D-028).

### Visual Standoff & Actor Separation

To prevent visual clutter and overlapping text in crowded scenes:
1. **Actor Physical Standoff (`get_entity_screen_layout`):** Entities sharing identical or near-identical world coordinates (within a 32px Euclidean radius) are automatically dispersed horizontally by ±30px in screen space.
2. **Text Collision Avoidance (`TextLayoutResolver`, D-024):** All floating labels are submitted with anchor coordinates, preferred offsets, font scales, categories, and priority tiers (`hover_tooltip = 10` down to `backdrop_prop = 1`). Living actor tokens and waypoint anchors register as rectangular obstacles.
3. **Visual Hierarchy:** Actor names use font scale 2 (12px character width) placed above tokens; actor status badges use font scale 1 (6px character width) placed below tokens. In contested spaces, status badges stagger downward across vertical tiers (Tiers 1-3) or flip above, while idle waypoint names yield to preserve legibility without hiding the physical ground anchor. Hover tooltips always take highest priority.

## Failure modes and observability

| Failure | User-visible behaviour | Detection | Recovery / runbook |
| --- | --- | --- | --- |
| Script Syntax or Semantic Error | File, line, one-based byte column, source excerpt, caret, and an optional suggestion; non-zero exit | `check_source` owns the lexer, parser, or codegen message and suggestion; the runner renders them with the original source (`bespoke check`, `compile`, or source `run`) | Correct the source at the caret |
| Corrupted or Truncated `.sav` File | Load failure badge in pause drawer; automatic fallback to backup | Magic (`BSV1`), version, or CRC32 checksum mismatch in `SaveManager.load_slot` | Transparently falls back to `<slot>.sav.bak` and restores valid state (D-020) |
| Missing Host Audio / Display Hardware | Silent warning; continues running in pure headless simulation | SDL init check failure (`SDL_Init`, `SDL_CreateWindow`, `SDL_OpenAudio`) | Falls back to deterministic headless simulation and offline audio buffers (D-001, D-019) |
| Studio Play Module Fails, Refuses a Package, or Traps (P47-06) | The Play window says why (a requester for a refused package or a module that will not start, the fault panel for a trap); the project window, compiler, and files are untouched | `WebAssembly.instantiate` rejects, `play_failure_len` is non-zero after `wasm_init`, or a call into the game throws | Run starts a fresh instance with the last build (D-195, D-192 item 5) |
| Studio Compiler Module Fails to Load or Traps | A blinking fault panel names the failure; the workspace stays, opens and saves projects, and Check offers Retry | `WebAssembly.instantiate` rejects, or a `studio_*` call throws | Retry starts a fresh instance; the page never stops at a dead screen (D-192 item 5) |
| Canvas Out-of-Bounds | Drawing outside the canvas is dropped | `Canvas.set_pixel` bounds check (`x < width`, `y < height`) | Drops the pixel silently, so shapes may cross the edge without overrunning the buffer (D-022, D-097) |

## Claims vs. code
