## Phase 44: Mystery and Puzzle Systems

Goal: give authors first-class tools for the adventure mechanics that older engines approximated: hints worked out from what the player does not yet know, evidence thresholds, confronting characters with facts, combinable spell vocabularies, and characters that choose actions by personality. Origin: a design conversation with a veteran adventure developer (2026-11-18). Placement relative to 1.0 is the maintainer's call (D-118); these items add language surface, so each one that lands before the freeze joins what 1.0 promises. Items are in value order.

- [x] P44-01 Hints derived from what the player does not know. A script declares goals and the facts each one needs; a hint query finds the nearest unmet need. Two layers: an automatic base case and authored overrides. The base case writes a tiered hint with no authored text, from the room the need lives in, to the thing involved, to the relation that must hold, using entity names, the topology, and the fact table. Authors override any tier per need, because some answers (an insult to learn, a derived conclusion) cannot be read off the fact table. The search is Holmesian first: frontier needs only, phrased from facts the player character knows, with the Doylian tiers over the whole goal graph as the fallback when the frontier is empty; each hint records which path produced it (D-126). The Holmesian path's full form depends on P44-05's per-character knowledge; once the player has learned a character's values (P45-05), Holmesian hints may reason from them. Acceptance: a goal with no hint text still yields three tiers; a transcript shows a Holmesian hint, then the fallback firing once the frontier is empty; one proof mixes generated and authored hints, and its headless transcript shows hints advancing as facts are learned. Done 2026-11-19 (session 110): `goal` blocks declare needs with a `met` fact pattern, `after` prerequisites, a room, and optional `hint <tier> "text"`; `src/hint.zig` queries them with no state of its own (D-134). `.bspk` v15 carries goals and a fixture pins it. ## Phase 45: Characters With Values

Goal: give characters a persistent, author-declared value system that drives their decisions and lines, so the player presents dilemmas and persuades rather than picks from a dialogue tree. Origin: the maintainer's earlier Compass Engine design document (Virtue Matrix and Dilemma loop), reviewed 2026-11-18; its data format, host plumbing, and generated vocabulary are not carried over. Builds on P44-05, which supplies options, private knowledge, and scoring. Placement relative to 1.0 follows Phase 44 (D-118). Items are in value order.

- [x] P45-01 Value axes. Authors declare their own axes, each with a virtue and two failure poles (Mercy between Vengeance and Condoning Harm); the engine names no axis. Each character's value is an integer from -10 to +10 stored as a ternary fact such as `Value(Valerius, Justice, 8)` with functional overwrite (D-007), and the inspector shows it. Acceptance: compiler tests for the declaration and range checks; a script with a new axis compiles with no engine change. Done 2026-11-21 (session 119): `axis <Virtue> between <Pole> and <Pole>` interns the virtue as a property relation bounded to -10..+10 (`src/value.zig`, D-144), so the fact is `Justice(Valerius, 8)` rather than a three-argument `Value` row; values are two's complement, out-of-range literals are compile errors, run-time writes clamp, and the inspector lists the signed value. `.bspk` v19 carries axes and a fixture pins it.
- [x] P45-02 Red lines. A character lists actions it never takes; red lines remove an option before any scoring, whatever the values say. Acceptance: VM tests show a vetoed option never chosen, including when it would score highest. Done 2026-11-21 (session 120): `red lines <Character>: <Option>, ...` is fixed program data (D-145); `decision.step` skips a vetoed option before scoring, a decision with every offered option vetoed chooses nothing, and a red line naming no option offered to that character, or one that vetoes a whole decision, is a compile error. `.bspk` v20 carries red lines and a fixture pins it.
- [x] P45-03 Dilemma resolution. A dilemma names an axis and a counter-axis; the decision delta is the axis value minus the counter-axis value plus modifiers read from world facts (a known criminal, a famine). The delta falls into a tier (strong, moderate, neutral, and the mirrored tiers toward the counter-axis), and the tier selects an authored line and an action. The neutral tier means "seek more information" and asks for evidence (P44-03). The source document added the two scores, which makes a low counter-value weaken the lean; the difference is the intended arithmetic. Acceptance: tests for each tier boundary and for modifiers; a character with no line for a tier gets a compile-time error rather than silence. Done 2026-11-21 (session 121): `dilemma` blocks weigh two declared axes plus `leans` lines into five fixed, mirrored tiers (7 and 3, D-146); the actor says the tier line, `Chose` records the action, and the cue fires. Neutral waits for evidence and weighs again on each new `Presented` fact; a missing tier and a tier acting on a red line are compile errors. `.bspk` v21 carries dilemmas and a fixture pins it.
- [x] P45-04 Value drift. Outcomes the player brings about shift a character's values over a long game. Drift is integer only (an accumulator per axis that moves the value one step at a threshold), bounded per dilemma, saved, and identical under replay and rewind; no fractional values enter the simulation. Acceptance: a save, rewind, and replay test reproduces the same drift; a bound test caps it. Done 2026-11-21 (session 122): a dilemma's `drifts N toward|away from <Axis> when <Fact>` lines add points on each rise after the first weighing; 5 points are one step, each dilemma moves an axis at most 2 steps, and points past the bound or the range are discarded (D-148). All state is facts on generated relations; a test saves, rewinds, and replays to the same facts. `.bspk` v22 carries drift and a fixture pins it.
- [x] P45-05 Persuasion as a puzzle. The player chooses which value to appeal to, which adds a modifier to that axis; a character's values are facts the player learns by watching and asking, and learned values feed Holmesian hints (P44-01). Acceptance: one dilemma resolves differently under two appeals, and the transcript shows the player learning the value that makes the winning appeal possible. Done 2026-11-21 (session 123): `appeals N to <Axis>` lines and the `appeal to <value>` frame or `host.appeal` add a one-weighing modifier, refused unless the player knows `<Axis> of <Character>`; values are learned by watching a non-neutral weighing in the same room or by a script answering a question, and hints treat such a need as Holmesian once the value is known (D-149). A host test shows one dilemma ending in Fine under a mercy appeal and Jail under a justice appeal, each after the player learns the value. `.bspk` v23.

Acceptance: a headless golden, a showcase page, and a hand-playable run.
