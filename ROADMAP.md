# Roadmap

Item IDs are permanent: `P<phase>-<nn>`. Never renumber; append new items at the end of their phase.
`[ ]` open · `[~]` in progress · `[x]` done · `[-]` dropped.

Phases 1 through 41 are complete and archived in [the November 2026 roadmap archive](docs/archive/ROADMAP_2026_11.md). The maintainer closed the first roadmap on 2026-11-15. Phase 42 covers BeSpoke 0.2.0; 1.0 remains deferred (D-118).

What the most recent phases taught:
- Phase 34 (loose ends): deferrals recorded inside finished items were real work, and each browser deck added to close one exposed a host gap (path routines started at load, walks that ignored locks, a bar the browser could not type into); the release pass itself was accepted on the maintainer's own play, with the macOS, Windows, and uploaded-site checks still unrun.
- Phase 35 (original proofs): a rewrite goes fastest as an approved draft that keeps every mechanic and transcript step and changes only names and lines; renaming turned up name collisions between proofs, and making each proof playable by hand on its own page turned up engine gaps that no transcript showed.
- Phase 36 (one presentation): once desktop and browser drew the same frame, each later browser page cost little; what still differed was host plumbing (how scripts start, how walks are planned, where doorways are), not drawing.
- Phase 38 taught that retiring source names and preserving serialized files require separate compatibility rules.
- Phase 39 taught that input limits need boundary tests and a CI pin needs a generated project build against the exact tag.
- Phase 40 taught that authoring tools stay in sync when the editor grammar comes from the lexer and CI runs the tutorial itself.
- Phase 41 taught that a synthetic load shows scaling costs, while a reference game shows whether they justify changing the engine.

## Era 2: BeSpoke 1.0 for Other Developers

Goal (maintainer, 2026-11-15): BeSpoke ships as an engine and language that other developers install to make their own games, supported on Linux desktop and in the browser. macOS and Windows are not 1.0 targets. Order: the toolchain moves first, so the surface that 1.0 freezes is written once against the Zig that users will have; input hardening comes before the freeze. Q-009 (license) and Q-010 (release hosting) are answered.

## Phase 44: Mystery and Puzzle Systems

Goal: give authors first-class tools for the adventure mechanics that older engines approximated: hints worked out from what the player does not yet know, evidence thresholds, confronting characters with facts, combinable spell vocabularies, and characters that choose actions by personality. Origin: a design conversation with a veteran adventure developer (2026-11-18). Placement relative to 1.0 is the maintainer's call (D-118); these items add language surface, so each one that lands before the freeze joins what 1.0 promises. Items are in value order.

- [x] P44-01 Hints derived from what the player does not know. A script declares goals and the facts each one needs; a hint query finds the nearest unmet need. Two layers: an automatic base case and authored overrides. The base case writes a tiered hint with no authored text, from the room the need lives in, to the thing involved, to the relation that must hold, using entity names, the topology, and the fact table. Authors override any tier per need, because some answers (an insult to learn, a derived conclusion) cannot be read off the fact table. The search is Holmesian first: frontier needs only, phrased from facts the player character knows, with the Doylian tiers over the whole goal graph as the fallback when the frontier is empty; each hint records which path produced it (D-126). The Holmesian path's full form depends on P44-05's per-character knowledge; once the player has learned a character's values (P45-05), Holmesian hints may reason from them. Acceptance: a goal with no hint text still yields three tiers; a transcript shows a Holmesian hint, then the fallback firing once the frontier is empty; one proof mixes generated and authored hints, and its headless transcript shows hints advancing as facts are learned. Done 2026-11-19 (session 110): `goal` blocks declare needs with a `met` fact pattern, `after` prerequisites, a room, and optional `hint <tier> "text"`; `src/hint.zig` queries them with no state of its own (D-134). `.bspk` v15 carries goals and a fixture pins it. The Observatory's `RecoverThePlate` reports a generated Holmesian room hint, an authored Holmesian relation hint, the Doylian fallback, and nothing once every need holds. D-126's literal fallback was unreachable in a finite acyclic graph; D-134 records the reading used.
- [x] P44-02 Evidence thresholds. A condition can count matching facts (x of y) or total weights on them (points toward a threshold), so an investigation moves on with enough evidence rather than all of it. `script_spec.md` has no aggregate expression today (checked 2026-11-18). Acceptance: parser, codegen, and VM tests for both forms; the spec documents them; fuzz corpora cover the new syntax. Done 2026-11-19 (session 111): a condition reads `2 of Clue(_)` for a count or `6 points of Clue(_)` for a total, with `_` wildcarding either argument and the matched fact's third slot as its weight. `query_count` and `query_points` carry a wildcard mask and a threshold; `VM.eval_condition` serves `wait until`, the compiled path and `eval_expr` serve `if` and choice guards, and the total is u64 so a long table cannot wrap. `.bspk` v16 carries the opcodes, a v16 fixture pins both in one routine, and the v15 fixture still loads. `tests/fixtures/fuzz/room.bespoke` scripts one of each.
- [x] P44-03 Confronting a character with a fact. A first-class "present X to Y" action reveals new facts depending on what that character knows, generalizing the Observatory's evidence-guarded rebuttals (P33-03). A character state may react to presented facts as they arrive (stress, composure), so a readout such as a heartbeat monitor responds to the systemic state rather than to fixed story beats. A character whose dilemma lands in the neutral tier (P45-03) asks to be shown evidence, which opens this action. Acceptance: the Observatory or a new proof uses the general form, with no transcript regression elsewhere. Done 2026-11-19 (session 112): `present <thing> to <thing>` and `show <thing> to <thing>` are engine frames for `Presents(actor, person, evidence)`, and `host.present` records `Presented(person, evidence)` before dispatch. `Presented` is a set fact, one row per distinct piece of evidence, so `1 of Presented(Pell, _)` serves a reaction state; the Observatory moves Pell from rattled to broken as the glove and slip arrive, and shows the slip to Moss, who does not know it, for no reveal. No new opcode, so `.bspk` stays 16. The sixth verb bar slot is deferred; the typed command and the proof's `[4]` key use the action (D-135).
- [x] P44-04 Combinable spell vocabularies. A declaration of tiered word sets (power, element, form) whose combinations resolve to actions, with invalid combinations rejected and each word gated by discovery. Complements drafts and weaving (D-029) instead of replacing them. Acceptance: compiler tests for the declaration and a small original proof in which the player discovers combinations unaided. In progress 2026-11-19 (session 113): `spellbook` declarations compile into `CompiledProgram.spellbooks`, `src/spell.zig` resolves a name or a triple and gates each word on `Knows`/`Believes` with `Rejects` overriding, `host.cast` fires the spell's own cue, `.bspk` v17 carries the book, and a v17 fixture is checked in (D-136). The Word Foundry (`proofs/word_foundry.zig`) teaches six words through three clues, resolves two triples, and refuses a third without changing state; its headless transcript is a golden. Done 2026-11-19 (session 113).
- [x] P44-05 Characters that choose by personality from what they know. Agendas cover pursuit and interception only (D-056). Add per-character private knowledge and a rule set that scores offered options against it, so a character picks one action per decision point. This item is the decision mechanism (options, knowledge, scoring); Phase 45 supplies the values that drive the scores, and the scoring rules are written in BeSpoke scripts (Q-015). Acceptance: a card-game proof (Hearts-style, original) in which each seat plays only from its own hand and its own inferences, deterministic under replay and rewind. In progress 2026-11-19 (session 114): `decision` declarations compile into `CompiledProgram.decisions`, `src/decision.zig` offers only the options the actor knows, sums `picks` and `drops` lines, breaks ties by declaration order, and fires the cue with the winner, and `.bspk` v18 carries decisions (D-137). The card-game proof is The Cinder Table (`proofs/cinder_table.zig`): three seats play four rounds, each playing only cards in its own hand, and Maren leads a second cinder once Ossic's discard makes the void public, which raises that lead from five points to ten. Its headless transcript is a golden and its replay after a restore makes the same twelve plays. Done 2026-11-19 (session 114).
- [x] P44-06 Watching another room. The simulation already runs in every room on the tick clock; establish whether a host can show a room the player is not in, and add the host API if it cannot. Acceptance: a proof lets the player observe a character acting elsewhere, and its render golden draws that view. Done 2026-11-20 (session 114): `DisplayBridge.capture_scene` fills a frame from a named room and labels it as that room, with that room's `SceneScore`, while `vm.current_scene` and every fiber state stay put; `capture_frame` is the same call with the VM's scene (D-138). The world already steps facts, motors, agendas, societies, grids, and decisions in every room, and `step_tick` runs every ready fiber, so only the view was missing (P44-07). The Long Gallery (`proofs/long_gallery.zig`) keeps Audra in the gallery while Corin's agenda catches Pell in the locked studio; pressing V watches it, the transcript checks the studio's contents and the read-only rule, and `render.txt` draws the watched frame.
- [x] P44-07 Off-screen routines in watched rooms. Establish whether a watched room's scripted routines run while the player looks in. Done 2026-11-20 (session 114) as a correction, not a feature: `step_tick` already runs every ready fiber, so a character's routine keeps running in every room and a watched room shows it without a live-scene set. `transition_to_scene` paused only fibers owned by the scene being left, which reached an ambient routine declared on a scene entity and no character routine; no script declares one, and D-139 retires that pause. The `P44-07` test in `src/vm.zig` pins a character fiber running while the player is elsewhere, and the rewritten `P12-01` test pins a fiber of the room left behind still running.

## Phase 45: Characters With Values

Goal: give characters a persistent, author-declared value system that drives their decisions and lines, so the player presents dilemmas and persuades rather than picks from a dialogue tree. Origin: the maintainer's earlier Compass Engine design document (Virtue Matrix and Dilemma loop), reviewed 2026-11-18; its data format, host plumbing, and generated vocabulary are not carried over. Builds on P44-05, which supplies options, private knowledge, and scoring. Placement relative to 1.0 follows Phase 44 (D-118). Items are in value order.

- [ ] P45-01 Value axes. Authors declare their own axes, each with a virtue and two failure poles (Mercy between Vengeance and Condoning Harm); the engine names no axis. Each character's value is an integer from -10 to +10 stored as a ternary fact such as `Value(Valerius, Justice, 8)` with functional overwrite (D-007), and the inspector shows it. Acceptance: compiler tests for the declaration and range checks; a script with a new axis compiles with no engine change.
- [ ] P45-02 Red lines. A character lists actions it never takes; red lines remove an option before any scoring, whatever the values say. Acceptance: VM tests show a vetoed option never chosen, including when it would score highest.
- [ ] P45-03 Dilemma resolution. A dilemma names an axis and a counter-axis; the decision delta is the axis value minus the counter-axis value plus modifiers read from world facts (a known criminal, a famine). The delta falls into a tier (strong, moderate, neutral, and the mirrored tiers toward the counter-axis), and the tier selects an authored line and an action. The neutral tier means "seek more information" and asks for evidence (P44-03). The source document added the two scores, which makes a low counter-value weaken the lean; the difference is the intended arithmetic. Acceptance: tests for each tier boundary and for modifiers; a character with no line for a tier gets a compile-time error rather than silence.
- [ ] P45-04 Value drift. Outcomes the player brings about shift a character's values over a long game. Drift is integer only (an accumulator per axis that moves the value one step at a threshold), bounded per dilemma, saved, and identical under replay and rewind; no fractional values enter the simulation. Acceptance: a save, rewind, and replay test reproduces the same drift; a bound test caps it.
- [ ] P45-05 Persuasion as a puzzle. The player chooses which value to appeal to, which adds a modifier to that axis; a character's values are facts the player learns by watching and asking, and learned values feed Holmesian hints (P44-01). Acceptance: one dilemma resolves differently under two appeals, and the transcript shows the player learning the value that makes the winning appeal possible.
- [ ] P45-06 The dilemma proof. An original proof built on the maintainer's own Captain Valerius and the stolen bread: Valerius's values, red lines, and tiered lines, two appeals, and drift carried into a later scene. Acceptance: a headless golden, a showcase page, and a hand-playable run.
